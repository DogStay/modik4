# Как запустить и проверить мод на сервере

## Главное про папку Profiles

**Папку `Profiles` создаёт сервер, а не мод — и только если передан параметр `-profiles=`.**

Мод создаёт внутри неё лишь свою подпапку. Цепочка такая:

```
-profiles=C:\DayZServer\Profiles      параметр запуска сервера
        ↓
$profile:                             движок разворачивает в этот путь
        ↓
$profile:JobsMod/                     мод создаёт при первом старте
```

Если `-profiles=` не передать, DayZ положит профиль в место по умолчанию, которое
на разных сборках отличается — и файлы конфига появятся не там, где вы их ищете.
**Всегда указывайте `-profiles=` явно.**

Если папка недоступна для записи, мод не падает: он работает на встроенных
настройках и пишет в лог, что правки конфига сохраняться не будут.

---

## 1. Сборка PBO

Из папок `JobsMod_Client/` и `JobsMod_Server/` собрать по одному PBO
(Addon Builder из DayZ Tools, либо `MakePbo` / `pboProject` из Mikero Tools).

Файл `$PBOPREFIX$` в каждой папке уже лежит и задаёт префикс — не удаляйте его.

## 2. Раскладка папок

```
DayZServer/
├── @JobsMod_Client/
│   └── addons/
│       └── JobsMod_Client.pbo
├── @JobsMod_Server/
│   └── addons/
│       └── JobsMod_Server.pbo
└── Profiles/                     ← создаст сервер сам
```

## 3. Запуск сервера

```
DayZServer_x64.exe ^
  -config=serverDZ.cfg ^
  -profiles=C:\DayZServer\Profiles ^
  -mod=@JobsMod_Client ^
  -serverMod=@JobsMod_Server ^
  -dologs -adminlog -netlog -freezecheck
```

Клиентская часть идёт в `-mod=`, серверная — в `-serverMod=`.
Серверную часть игроки не скачивают.

## 4. Запуск клиента

В параметрах запуска игры: `-mod=@JobsMod_Client`

Клиенту нужен **только** клиентский мод.

## 5. Структура конфигурации

При первом запуске мод создаёт дерево файлов. **Имя файла = id сущности.**

```
Profiles/JobsMod/
├── settings.json                  общие настройки
├── Zones/
│   └── zones.json                 список регионов
├── PilePoints/
│   ├── pile_01.json               ← одна точка мусора = один файл
│   ├── pile_02.json
│   └── pile_03.json
├── LoaderAreas/
│   └── loader_area_01.json        маршрут грузчика
├── Jobs/
│   ├── job_trash_sorter.json      ← одна работа = один файл
│   ├── job_cargo_loader.json
│   └── job_courier.json
└── NPC/
    ├── npc_sorter_01.json         ← один NPC = один файл
    ├── npc_loader_01.json
    ├── npc_dispatcher_01.json     выдаёт работу посыльного
    └── npc_recipient_01.json      принимает посылку, работ не выдаёт
```

Чтобы добавить NPC или работу — положите в нужную папку ещё один `.json`.
Чтобы убрать — удалите файл. После правок нужен перезапуск сервера.

**Дефолты создаются один раз**, признак первого запуска — отсутствие
`settings.json`. Если он есть, мод грузит только то, что реально лежит в папках,
и удалённый NPC уже не вернётся.

> **Обновление с версии 2.1.** Работа посыльного и два её NPC — это дефолты, а
> дефолты пишутся только при первом запуске. На сервере, где `settings.json` уже
> лежит, они **не появятся сами**: создайте `Jobs/job_courier.json`,
> `NPC/npc_dispatcher_01.json` и `NPC/npc_recipient_01.json` руками по образцам
> ниже. Либо удалите всю папку `Profiles/JobsMod` — тогда дерево создастся
> заново, но ваши правки пропадут.

### settings.json

```json
{
    "pile_respawn_seconds": 300,
    "assignment_timeout_seconds": 3600,
    "debug_logging": true
}
```

| Поле | Смысл |
|---|---|
| `pile_respawn_seconds` | Через сколько отработанная куча вернётся на свою точку. |
| `assignment_timeout_seconds` | Сколько игрок может держать невыполненную работу. По истечении работа снимается, а её ящики удаляются. |
| `debug_logging` | Подробный лог. Для отладки — `true`. |

### Zones/zones.json

Зона — это только группировка и название, которое игрок видит на HUD.
Никакой геометрии у неё нет.

```json
{
    "zones": [
        { "id": "zone_01", "name": "Черногорск" },
        { "id": "zone_02", "name": "Электрозаводск" }
    ]
}
```

### PilePoints/pile_01.json

**Точная точка, а не радиус.** Куча ставится ровно туда, куда вы её поставили.

```json
{
    "id": "pile_01",
    "zone_id": "zone_01",
    "name": "Куча у площади",
    "x": 6600.0,
    "y": 0.0,
    "z": 2500.0
}
```

`y = 0` означает «поставить на грунт». Координаты снимаются в игре командой
`#position` — встаньте там, где должна стоять куча, и впишите x и z.

### NPC/npc_sorter_01.json

```json
{
    "id": "npc_sorter_01",
    "name": "Иван",
    "description": "Нанимаю на уборку.",
    "position": { "x": 6620.0, "y": 0.0, "z": 2520.0 },
    "rotation": 45.0,
    "player_class": "SurvivorM_Mirek",
    "invulnerable": true,
    "clothing": ["TShirt_Grey", "Jeans_Blue", "WorkingBoots_Grey"],
    "jobs": ["job_trash_sorter"]
}
```

| Поле | Смысл |
|---|---|
| `position` | Где стоит. `y = 0` — поставить на грунт. |
| `rotation` | Куда смотрит, 0–360°. |
| `player_class` | Любой ванильный класс выжившего. |
| `invulnerable` | `true` — урон по нему не проходит вообще. |
| `clothing` | Просто список класснеймов. Что напишете — то и наденет. |
| `jobs` | Какие работы выдаёт. Максимум 6 — столько строк в меню. |

`jobs` можно оставить пустым — **но только у получателя посылки.** NPC, который
не выдаёт работ и не указан ни в одной работе как `target_npc_id`, при загрузке
отбрасывается: стоять просто так ему незачем.

```json
{
    "id": "npc_recipient_01",
    "name": "Гриша",
    "description": "Жду посылку от Марины. Больше ничего не жду.",
    "position": { "x": 10484.0, "y": 0.0, "z": 2264.0 },
    "rotation": 90.0,
    "player_class": "SurvivorM_Denis",
    "invulnerable": true,
    "clothing": ["Hoodie_Blue", "Jeans_Black", "WorkingBoots_Brown"],
    "jobs": []
}
```

### Jobs/job_trash_sorter.json — работа дворника

```json
{
    "id": "job_trash_sorter",
    "name": "Сортировщик мусора",
    "description": "Разберите мусор на трёх точках в Черногорске.",
    "type": "sorting",
    "zone_id": "zone_01",
    "reward": 100,
    "cooldown_seconds": 300,
    "piles_required": 3
}
```

### Jobs/job_cargo_loader.json — работа грузчика

```json
{
    "id": "job_cargo_loader",
    "name": "Грузчик",
    "description": "Перенесите ящики со склада в зону разгрузки.",
    "type": "loading",
    "zone_id": "zone_02",
    "loader_area_id": "loader_area_01",
    "reward": 150,
    "cooldown_seconds": 600,
    "cargos_required": 5,
    "cargo_class": "JobsMod_CargoBox"
}
```

`cargo_class` — любой класснейм предмета. `JobsMod_CargoBox` — ящик мода:

- **в инвентарь не влезает нигде** — его размер 20×20 больше любой сетки в игре
  (рюкзак, разгрузка, палатка, машина, бочка). Только руки или земля.
- **весит 60 кг** и помечен как тяжёлый предмет: бежать с ним нельзя, персонаж
  идёт шагом и выносливость уходит сразу.
- внутрь ничего не положишь — своего груза у него нет.

### Jobs/job_courier.json — работа посыльного

```json
{
    "id": "job_courier",
    "name": "Посыльный",
    "description": "Доставьте опечатанный пакет в Электрозаводск.",
    "type": "messenger",
    "zone_id": "zone_02",
    "reward": 250,
    "cooldown_seconds": 1800,
    "target_npc_id": "npc_recipient_01",
    "package_class": "JobsMod_Parcel"
}
```

| Поле | Смысл |
|---|---|
| `zone_id` | Зона **назначения** — то, что игрок видит на HUD. Не место выдачи. |
| `target_npc_id` | Кому нести. Этот NPC принимает пакет **и платит** — не тот, кто выдал работу. |
| `package_class` | Класснейм пакета. По умолчанию `JobsMod_Parcel`. |
| `cooldown_seconds` | 1800 = полчаса до повторного взятия именно этой работы. |

`JobsMod_Parcel` — предмет мода, который нельзя потерять по своей воле:

- **не выбросить и не переложить** — предмет отказывается покидать то место в
  инвентаре, куда его положил сервер;
- **не взять в руки, не открыть, не использовать** — действий у него нет вообще;
- **не поднять с земли**, если он там как-то оказался;
- **исчезает вместе с работой** — при сдаче, отказе, смерти, выходе с сервера и
  по истечении `assignment_timeout_seconds`.

Раз в 15 секунд сервер сверяет пакеты с заданиями: пакет без работы удаляется,
работа без пакета закрывается. Именно поэтому пакет не переживает ни падение
сервера, ни переподключение.

Если указать в `package_class` любой другой предмет, он будет обычным: выбросить
его можно, и остаётся только серверная сверка.

### LoaderAreas/loader_area_01.json

```json
{
    "id": "loader_area_01",
    "name": "Склад Электрозаводска",
    "zone_id": "zone_02",
    "source":      { "x": 10400.0, "z": 2200.0, "radius": 12.0 },
    "destination": { "x": 10500.0, "z": 2300.0, "radius": 10.0 }
}
```

`source` — где появляются ящики. `destination` — куда их нести.
Если круги пересекаются, ящик засчитается сразу на месте — мод об этом
предупредит в логе при старте.

## 6. Как это работает в игре

### Дворник

1. Подойти к NPC → действие **«Поговорить о работе»**.
2. В меню выбрать «Сортировщик мусора» → работа принята, в левом углу появляется
   панель задания с прогрессом `0 / 3`.
3. Дойти до кучи в своей зоне → действие **«Сортировать мусор»** → мини-игра.
4. Разложить 9 предметов → куча исчезает, прогресс `1 / 3`.
5. После `3 / 3` панель пишет «Вернитесь к нанимателю».
6. Вернуться к NPC → в меню кнопка **«СДАТЬ РАБОТУ»** → выплата.

Куча вне зоны своей работы даст отказ. Без взятой работы сортировка недоступна
вообще — NPC это единственный вход в работу.

### Грузчик

1. Взять работу у второго NPC → на складе появляются ящики (столько, сколько
   написано в `cargos_required`).
2. Подойти к ящику, взять его в руки обычным «Взять в руки» — персонаж несёт его
   двумя руками, как генератор.
3. Донести до зоны разгрузки и **положить на землю** обычным сбросом из рук.
4. Ящик исчезает, прогресс +1. Пока ящик в руках — он не засчитывается.
5. После последнего ящика — назад к NPC за расчётом.

Отдельных действий «взять груз» и «поставить груз» нет: мод пользуется штатной
механикой рук, а сервер раз в 2 секунды проверяет, не лежит ли ящик в зоне
разгрузки.

### Посыльный

1. Взять работу у диспетчера → пакет сразу оказывается в инвентаре, панель
   задания пишет «Доставьте пакет: Гриша».
2. Дойти до получателя — метка ведёт прямо к нему.
3. Навести на получателя → **«Поговорить о работе»** → кнопка **«СДАТЬ РАБОТУ»**.
4. Пакет исчезает, приходит расчёт, включается получасовой перерыв.

Отдельного шага «получить пакет» нет: работа и есть пакет. Промежуточного
прогресса тоже нет — панель показывает `0 / 1` до самой сдачи, потому что до
сдачи ничего не доставлено.

Отказаться от работы можно у кого угодно — пакет удалится вместе с ней. Умереть
с пакетом можно, но пакет умрёт вместе с игроком: в трупе его не останется.

Одновременно можно держать **только одну работу любого типа**. Пока пакет не
сдан, дворник и грузчик в меню будут помечены как недоступные.

### 3D-метка

Пока у игрока есть работа, в мире висит метка с названием точки и расстоянием
до неё. Видит её только тот, кто взял работу.

Метка всегда одна — та, которая нужна прямо сейчас:

| Состояние | Куда показывает |
|---|---|
| Дворник, работа идёт | Ближайшая **стоящая** куча в вашей зоне |
| Грузчик, руки пустые | Зона погрузки |
| Грузчик, ящик в руках | Зона разгрузки |
| Посыльный | Получатель — там, где он реально стоит |
| Работа выполнена | NPC, который её принимает |

Если точка за спиной или вне экрана — метка прижимается к краю экрана и
показывает, в какую сторону идти, а не пропадает.

Отработанная куча из списка меток исчезает сразу: сервер шлёт новый список в тот
же момент, когда засчитывает прогресс.

## 7. Что смотреть в логе

Файл `.RPT` в папке `Profiles`. Все строки мода начинаются с `[JobsMod]`.

Успешный старт выглядит так:

```
[JobsMod] INFO:  SERVER/CONFIG: $profile:JobsMod пуст, создаётся конфигурация по умолчанию.
[JobsMod] INFO:  SERVER/CONFIG: зон 3, точек мусора 3, маршрутов 1, работ 3, NPC 4.
[JobsMod] INFO:  SERVER/CONFIG:   куча 'pile_01' в зоне 'zone_01' на X 6600 / Z 2500.
[JobsMod] INFO:  SERVER/CONFIG:   работа 'job_trash_sorter' (sorting) в зоне 'zone_01', награда 100, кулдаун 300 с.
[JobsMod] INFO:  SERVER/CONFIG:   работа 'job_courier' (messenger) в зоне 'zone_02', награда 250, кулдаун 1800 с, получатель 'npc_recipient_01', пакет 'JobsMod_Parcel'.
[JobsMod] INFO:  SERVER/CONFIG:   NPC 'npc_sorter_01' (Иван) на X 6620 / Z 2520, работ 1.
[JobsMod] INFO:  SERVER/CONFIG:   NPC 'npc_recipient_01' (Гриша) на X 10484 / Z 2264, работ 0, принимает посылки.
[JobsMod] INFO:  SERVER/NPC: создано NPC: 4 из 4.
[JobsMod] INFO:  SERVER/ZONES: создано куч мусора: 3 из 3 точек.
[JobsMod] INFO:  SERVER: JobsMod запущен. Build: 2.2.0-courier; protocol=3.
```

### Если что-то не так

| Строка в логе | Что означает |
|---|---|
| `записать ... не удалось` + `проверьте параметр -profiles=` | Профиль не задан или только для чтения. Мод работает, но конфиг не сохранится. |
| `... не разобран (...)` | Ошибка синтаксиса в конкретном JSON. Файл пропущен, остальные загрузились. |
| `ссылается на неизвестную зону` | В работе или точке указан `zone_id`, которого нет в `zones.json`. |
| `ссылается на неизвестную работу` | В NPC указан `job_id`, которого нет в `Jobs/`. |
| `класс '...' для NPC ... не создан` | Неверный `player_class`. |
| `не удалось надеть '...'` | Неверный класснейм в `clothing`. NPC создан, но раздетый. |
| `ни одной кучи не создано` | Координаты точек не подходят текущей карте. |
| `ни один NPC не создан` | То же самое для NPC. |
| `зоны погрузки и разгрузки пересекаются` | Маршрут грузчика настроен так, что ящик засчитается на месте. |
| `адресована неизвестному NPC` | В работе посыльного `target_npc_id` указывает на NPC, которого нет в `NPC/`. Работа отброшена. |
| `не задан target_npc_id` | Работа с `"type": "messenger"` без получателя. Работа отброшена. |
| `адресованную самому себе` | Диспетчер и получатель — один и тот же NPC. Ссылка убрана. |
| `не выдаёт работ и не принимает посылок` | NPC с пустым `jobs`, на которого никто не ссылается. Отброшен. |
| `найден пакет без задания, удалён` | Штатная уборка: у игрока был пакет от закрытой работы. |
| `пакет задания ... потерян, работа закрыта` | Пакет покинул игрока (например, вместе со сброшенным рюкзаком). |
| `не осталось ни одной корректной работы` | Мод не стартовал: выдавать нечего. |
| строк `[JobsMod]` нет вообще | Серверный PBO не загрузился — проверьте `-serverMod=` и путь. |

## 8. Порядок проверки

1. Сервер стартовал, в логе есть `SERVER: JobsMod запущен`, число NPC и число куч.
2. Прийти на координаты NPC — он стоит, одет, смотрит в заданную сторону.
3. Выстрелить в NPC — урона нет, он не падает (при `invulnerable: true`).
4. Навести на NPC → действие **«Поговорить о работе»** → открылось меню.
5. Взять работу дворника → в левом углу появилась панель с `0 / 3`.
6. Подойти к куче → **«Сортировать мусор»** → мини-игра открылась, в шапке имя зоны.
7. Разложить всё → куча пропала, панель показывает `1 / 3`.
8. Дойти до `3 / 3` → панель пишет «Вернитесь к нанимателю».
9. Вернуться к NPC → кнопка «СДАТЬ РАБОТУ» → в инвентаре «Расчётный жетон» на 100.
10. Сразу взять ту же работу → отказ «Вы недавно закончили эту работу».
11. Взять работу грузчика → на складе появились ящики, метка показывает на зону
    погрузки.
12. Попробовать положить ящик в рюкзак / палатку / машину → не влезает никуда.
13. Взять ящик в руки → метка переключилась на зону разгрузки; попробовать
    побежать → бежать нельзя, только шагом.
14. Дойти до зоны разгрузки, положить на землю → ящик исчез, прогресс +1.
15. Пронести ящик через зону разгрузки не выпуская из рук → прогресс не меняется.
16. Отвернуться от метки → она прижалась к краю экрана, а не исчезла.
17. Выйти с сервера с невыполненной работой и зайти обратно → работа снята,
    ящики убраны из мира.
18. Взять работу посыльного → пакет появился в инвентаре, панель пишет
    «Доставьте пакет».
19. Попробовать выбросить пакет, перетащить его в рюкзак, в палатку, в машину,
    взять в руки → ни одно действие не проходит.
20. Взять работу посыльного при полном инвентаре → отказ «Освободите место».
21. Пока пакет при вас — открыть меню дворника → его работа помечена
    «Сначала закончите текущую работу».
22. Дойти до получателя → **«СДАТЬ РАБОТУ»** → пакет исчез, пришёл расчёт.
23. Сразу попробовать взять работу снова → отказ «Вы недавно закончили».
24. Взять работу заново после сброса кулдауна и умереть с пакетом → в трупе
    пакета нет, работа снята.
25. Взять работу, выйти с сервера, зайти обратно → пакета нет, работы нет.

### Быстрая проверка без ожидания

```json
"pile_respawn_seconds": 10
```
и в работах `"cooldown_seconds": 0`, `"piles_required": 1`, `"cargos_required": 1`.

## 9. Известные места, требующие проверки в игре

Эти вещи не удалось подтвердить без запуска — при первой проверке смотрите на них:

- **Класснеймы по умолчанию.** `SurvivorM_Mirek`, `SurvivorM_Boris`,
  `SurvivorF_Judy`, `SurvivorM_Denis`, `TShirt_Grey`, `Jeans_Blue`,
  `WorkingBoots_Grey`, `Hoodie_Black`, `Hoodie_Blue`, `CargoPants_Grey`,
  `CanvasPants_Beige`, `Jeans_Black`, `RaincoatJacket_Yellow`,
  `AthleticShoes_Black`, `WorkingBoots_Yellow`, `WorkingBoots_Brown`. Если класс
  не существует — в логе будет прямое сообщение, правится в файле NPC.
- **Пакет посыльного.** `JobsMod_Parcel` берёт модель у ванильного
  `VitaminBottle`, а поведение — у собственного скрипт-класса (`extends
  ItemBase`), то есть намеренно теряет всё, что умеет пузырёк с витаминами.
  Проверить надо две вещи: что пакет вообще создаётся в инвентаре, и что его
  правда никуда не перетащить. Если создание не проходит — виноват
  `CanPutInCargo` в `JobsMod_Parcel.c`; если предмет выглядит не так, меняется
  родитель в `JobsMod_Client/config.cpp`.
- **Смерть с пакетом.** Уборка висит на `EEKilled`. Если пакет всё-таки остаётся
  в трупе, его подберёт серверная сверка в течение 15 секунд — но это уже
  запасной путь, а не основной.
- **Ящик в руках.** `JobsMod_CargoBox` наследует ванильный `WoodenCrate` — расчёт
  на то, что он берётся в руки и несётся двумя руками. Если анимация не та,
  меняется родитель в `JobsMod_Client/config.cpp`.
- **Запрет бега.** Держится на двух вещах: `weight = 60000` и `itemBehaviour = 2`.
  Размер 20×20 — тот механизм, который гарантированно не пускает ящик в инвентарь,
  и он от анимации не зависит. Если бежать всё-таки получается, поднимите вес
  либо добавьте скрипт-класс с запретом на спринт.
- **Проекция метки** опирается на `GetScreenPosRelative`. Если метка окажется
  смещена относительно объекта, правится в `JobsModWorldMarker.Project`.
- **Куча мусора тоже наследует `WoodenCrate`** и её, скорее всего, можно взять
  в руки и унести. На геймплей это не влияет (унесённая куча просто перестаёт
  быть рабочей точкой до респавна), но если это мешает — нужен отдельный
  родитель для `JobsMod_TrashPile`.
- **Имена ванильных классов для превью** в `JobsModTrashCatalog.c`. Если класса
  нет, карточка покажет название текстом вместо модели.
- **Шрифты.** Доступны только два ванильных, поэтому точные кегли из дизайн-спеки
  не воспроизводятся один в один.
