# Как запустить и проверить мод на сервере

## Главное про папку Profiles

**Папку `Profiles` создаёт сервер, а не мод — и только если передан параметр `-profiles=`.**

Мод создаёт внутри неё лишь свою подпапку. Цепочка такая:

```
-profiles=C:\DayZServer\Profiles      параметр запуска сервера
        ↓
$profile:                             движок разворачивает в этот путь
        ↓
$profile:JobsMod/janitor.json         мод создаёт при первом старте
```

Если `-profiles=` не передать, DayZ положит профиль в место по умолчанию, которое
на разных сборках отличается — и файл конфига появится не там, где вы его ищете.
**Всегда указывайте `-profiles=` явно.**

Если папка недоступна для записи, мод не падает: он работает на встроенных
настройках и пишет в лог, что правки конфига сохраняться не будут.

---

## 1. Сборка PBO

Из папок `JobsMod_Client/` и `JobsMod_Server/` собрать по одному PBO
(Addon Builder из DayZ Tools, либо `MakePbo` / `pboProject` из Mikero Tools).

Файл `$PBOPREFIX$` в каждой папке уже лежит и задаёт префикс — не удаляйте его.

## 2. Раскладка папок

```
DayZServer/
├── @JobsMod_Client/
│   └── addons/
│       └── JobsMod_Client.pbo
├── @JobsMod_Server/
│   └── addons/
│       └── JobsMod_Server.pbo
└── Profiles/                     ← создаст сервер сам
```

## 3. Запуск сервера

```
DayZServer_x64.exe ^
  -config=serverDZ.cfg ^
  -profiles=C:\DayZServer\Profiles ^
  -mod=@JobsMod_Client ^
  -serverMod=@JobsMod_Server ^
  -dologs -adminlog -netlog -freezecheck
```

Клиентская часть идёт в `-mod=`, серверная — в `-serverMod=`.
Серверную часть игроки не скачивают.

## 4. Запуск клиента

В параметрах запуска игры: `-mod=@JobsMod_Client`

Клиенту нужен **только** клиентский мод.

---

## 5. Что смотреть в логе

Файл `.RPT` в папке `Profiles`. Все строки мода начинаются с `[JobsMod]`.

Успешный старт выглядит так:

```
[JobsMod] INFO:  SERVER/CONFIG: $profile:JobsMod/janitor.json не найден, создаётся файл с настройками по умолчанию.
[JobsMod] INFO:  SERVER/CONFIG: принято зон: 3; кулдаун игрока 120 с; респавн кучи 300 с.
[JobsMod] INFO:  SERVER/CONFIG:   зона 'Черногорск, площадь' X 6600 / Z 2500, радиус 30, куч 2.
[JobsMod] INFO:  SERVER/ZONES: создано куч мусора: 6 в 3 зонах.
[JobsMod] INFO:  SERVER: JobsMod запущен. Build: 2.0.0-janitor; protocol=1.
```

### Если что-то не так

| Строка в логе | Что означает |
|---|---|
| `записать ... не удалось` + `проверьте параметр -profiles=` | Профиль не задан или только для чтения. Мод работает, но конфиг не сохранится. |
| `не удалось разобрать ... janitor.json` | Ошибка синтаксиса JSON. Исправьте или удалите файл — он создастся заново. |
| `ни одной кучи не создано` | Координаты зон не подходят текущей карте. См. ниже. |
| `каталог мусора некорректен` | Правка `JobsModTrashCatalog.c` нарушила правило 3 предмета на контейнер. |
| строк `[JobsMod]` нет вообще | Серверный PBO не загрузился — проверьте `-serverMod=` и путь. |

## 6. Настройка зон

Файл `Profiles/JobsMod/janitor.json`:

```json
{
    "player_cooldown_seconds": 120,
    "pile_respawn_seconds": 300,
    "debug_logging": true,
    "zones": [
        {
            "name": "Черногорск, площадь",
            "x": 6600.0,
            "z": 2500.0,
            "radius": 30.0,
            "piles": 2
        }
    ]
}
```

| Поле | Смысл |
|---|---|
| `player_cooldown_seconds` | Пауза между сменами для одного игрока. `0` — без паузы. |
| `pile_respawn_seconds` | Через сколько отработанная куча вернётся в свою зону. |
| `debug_logging` | Подробный лог. Для отладки — `true`. |
| `name` | Показывается в шапке меню как «Рабочая зона: …». |
| `x`, `z` | Центр зоны. Высота не задаётся — куча всегда ставится на грунт. |
| `radius` | Радиус разброса куч. Минимум 3 м. |
| `piles` | Сколько куч в зоне. Максимум 20. |

**Координаты по умолчанию рассчитаны на Chernarus.** На другой карте кучи уйдут
в никуда — возьмите координаты своей точки командой `#position` в игре
(или из редактора) и впишите `x` и `z`.

После правки файла — перезапуск сервера.

## 7. Порядок проверки

1. Сервер стартовал, в логе есть `SERVER: JobsMod запущен` и число созданных куч.
2. Зайти на координаты зоны — на земле должны стоять деревянные ящики (`JobsMod_TrashPile`).
3. Навести на кучу — в меню действий появится **«Сортировать мусор»**.
4. Выполнить действие — должно открыться меню сортировки, в шапке имя зоны из конфига.
5. Перетащить предмет в верный контейнер — оливковая вспышка, счётчик `1 / 3`, заполнен один pip.
6. Перетащить в неверный — красная вспышка, тряска бака, предмет вернулся, прогресс не изменился.
7. Разложить все 9 — окно «СОРТИРОВКА ЗАВЕРШЕНА», кнопка «ЗАВЕРШИТЬ РАБОТУ».
8. Нажать её — меню закрывается, приходит уведомление о начислении, в инвентаре
   появляется «Расчётный жетон», куча из мира исчезает.
9. Подойти к другой куче сразу — отказ «Вы недавно закончили смену».

### Быстрая проверка без ожидания

Чтобы не ждать кулдаунов при отладке, поставьте в конфиге:

```json
"player_cooldown_seconds": 0,
"pile_respawn_seconds": 10
```

## 8. Известные места, требующие проверки в игре

Эти вещи не удалось подтвердить без запуска — при первой проверке смотрите на них:

- **Имена ванильных классов для превью** (`Barrel_Green`, `WoodenPlank`,
  `SheetMetal`, `Pot`, `Canteen`, `CanisterGasoline`, `WoodenStick`, `Firewood`,
  `WaterBottle`, `BakedBeansCan`). Если класса нет, карточка покажет название
  текстом вместо модели, а в логе будет `превью ... недоступно`. Правится в
  `JobsModTrashCatalog.c`.
- **Родители предметов** в `JobsMod_Client/config.cpp` (`WoodenCrate`,
  `VitaminBottle`). Если такого класса нет — предмет сломается целиком, это
  серьёзнее превью.
- **Шрифты.** Доступны только два ванильных, поэтому точные кегли из дизайн-спеки
  (26px заголовок, 64px счёт) не воспроизводятся один в один.
